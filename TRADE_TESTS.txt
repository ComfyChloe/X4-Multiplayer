X4 LAN Lab — evidence report, updated for v5 on 10 October 2026

FIRST REAL TWO-COMPUTER SESSION — USER REPORT
The user and a friend connected real Linux and Windows X4 games over ZeroTier.
Additional Windows mods were disabled and the test mod reinstalled before the
loading crash stopped. Both peers appeared in the Linux relay log and Linux
reported remote=receiving. The user reported very poor performance and a lost
connection in less than 30 seconds. The exact conflicting mod, performance cost
and disconnect cause remain unresolved. This is not a passed endurance, shared
trade or combat test. Version 4 adds visibility and English packaging, not a
verified performance fix. Its console needs observation during the next session.

V4 DOCKING / LEAVING THE SEAT — USER REPORT AND LOGS
Both players saw each other. The user then docked and left the pilot seat / walked
onto the station. At 14:23:41 UTC the Linux host's network traffic stopped; the
remote Windows client continued sending. The host timed out five seconds later.
The Linux game log continued recording world/economy states after docking, without
a BUBBLE STOPPED error. The adapter had an early return for a zero controlled-ship
ID, which prevents every network update while on foot. This matches the report.

V5 REGRESSION CHECKS
The seat-transition test fails against v4 and passes after keeping the original
session ship while on foot. Both slots remain connected through 90 simulated
seconds using the real Lua client and Python relay with engine API doubles. World
publication and the trade frame callback continue. Returning to the same ship
keeps the same lease. Destroyed ships, other ships and sector changes still stop.
The server and client now time out at 30 seconds. Short interruptions preserve
the connection; invalid replies do not renew the client. Pose freshness stays
at 0.75 seconds. All 80 automated tests pass, none skipped. This is not a live
Windows/Linux gameplay result. Repeat docking, walking and returning in game.

AUTOMATED AND SAVE CHECKS
The earlier market implementation passed 62 automated tests with none skipped:
real local UDP, LuaJIT/native Linux I/O, trade hooks, fragments, deduplication,
startup ordering and installer protections. The current 80-test v5 result is
recorded in AUTOMATED-TESTS.txt (source: reports/automated-v5-tests.txt).

SHARED SCOPE AND LIMITATIONS
Two players, two LAN trading stations, six container wares, variable quantities,
buy/sell/mixed baskets and separate balances. Fixed station prices; host executes.
The rest of the universe and NPC economy run independently. Additional AI traders,
build storage, other stations, arbitrary cargo magnets, ship/sector changes,
PvP/destruction and persistent multiplayer saves are not accepted features.
Container pickup is the separate COLLECT-CONTAINER command. Partial native
transactions have no safe automatic rollback. On uncertain outcomes, restart
both test worlds and the relay before further cargo or trading actions.
