Internal test · 23 October 2026 · Windows/Linux · Two players

Both players now load one host-created starting save. This aligns the initial world; a persistent campaign and continuous shared station economy are still unfinished.

Before starting

Use X4 9.00, Steam build23660954, and matching enabled official DLC including Timelines. Both packages include the server and Python runtime. Close X4 and the previous server, remove the old mod using its original 5-REMOVE-MOD, then extract the complete new archive into a new folder.

Setup imports your normal display, sound and control preferences without changing that normal profile. Choose your usual profile if several are found. 9-IMPORT-SETTINGS repeats this copy later. Starts preserve custom resolution and bindings. Only the test safeguards autosave=false and uisafemode=false are required.

Host: create the shared world once

  1. Run 1-INSTALL, choose H and enter your reachable LAN/ZeroTier IPv4 address.
  2. Run 2-PREPARE-WORLD. X4 opens a disposable new world, saves it and closes automatically. Wait for Shared world ready. Do not play or load another save during preparation.
  3. Send JOIN-SESSION.json privately to the guest.
  4. Run 2-START-SERVER and keep its console open.
  5. Run 3-START-X4-TEST. The shared save loads automatically and your Shuttle appears after setup.

Guest: receive and load

  1. Keep the received JOIN-SESSION.json in your extracted package folder. Run 1-INSTALL, choose G and enter the invitation's path when asked.
  2. Run 2-TEST-CONNECTION, then 3-START-X4-TEST.
  3. The launcher downloads and checks the host world before opening X4. Wait through automatic loading; do not select another save. Stay in the pilot seat until Shuttle setup completes.

Windows: use the numbered .cmd files. Linux: run the corresponding .sh files from a terminal, such as bash 1-INSTALL.sh; use another terminal while the server is running.

Network and roles

Allow UDP45841 and TCP45844 to the host on the private test network. The connection check uses UDP; world transfer additionally needs TCP. A working ZeroTier connection needs no router forwarding. Keep the firewall enabled. The host must run both X4 and the included server; the Python server alone does not simulate X4.

Restart, diagnostics and removal

For every retry stop both games and the relay, then restart the relay and both games. Both reload the same starting save; progress from the previous attempt is not resumed. Use a fresh extracted pair and invitation for a different world. Preparation will not replace an existing world.

Read NEXT-TEST.txt for the focused station and docking test. The existing cargo, radar and Cooperative Trial human results are retained; repeat them only if a regression appears.

Run 4-DIAGNOSTICS on both PCs before restarting after a failure. Include roles/OS, approximate time, sector and station code. Keep private session files out of public reports. 7-VERIFY-PACKAGE checks package files; configured role files are checked separately.

Close X4 and the relay, then run 5-REMOVE-MOD from its owning package. Only the recorded, byte-matching save_010 copy in profile45841 is removed; the package retains its immutable world bundle and archives its mod. Other or changed saves are preserved. Never load or save normal campaigns in this test profile.

Content differences and limits

Different DLC/mod sets stop shared-world loading. No Workshop selections are rewritten and the withdrawn7.2 isolation helper is not included. A separate profile alone does not isolate the Steam account. Compare content manually if the launcher reports a difference.

Station construction/destruction and economy are not continuously synchronized. General NPC commands/combat, persistent campaign resume, normal shared missions and ingame text chat remain unfinished. Check RELEASE-CHECKS.txt for measured evidence and pending native Windows/two-player tests.
