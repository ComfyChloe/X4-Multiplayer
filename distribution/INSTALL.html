X4 LAN Lab · Version {{VERSION}} · 11 October 2026

Two players. One cooperative fleet.

Linux hosts the session and runs player 1. Windows 11 joins as player 2. A live server console can stay on your second monitor.

Internal W01: NPC scene synchronization. The host supplies actual NPC ships for the guest's current sector. This is the first shared-universe engineering milestone; ordinary cargo, NPC combat and the wider economy are still missing. Replace both packages and the relay, start fresh test worlds, and read WORLD-SYNC-TEST.txt before testing. Public Test 01 remains withheld. Read RELEASE-CHECKS.txt for actual verification.

The complete release includes exclusive Full HD, Low graphics, a 60 FPS cap and the OneDrive fix. Both players and the server must use the matching pair from this release folder.

1 · Prepare both computers

  • Use X4 9.00 (611726), Steam build 23660954 on both computers. The installers reject different builds. Keep the same DLC selection.
  • Disable other third-party mods for this test. Official DLC can remain enabled. One Windows loading crash disappeared after other mods were disabled and this mod was reinstalled; the individual conflicting mod has not been identified.
  • Unpack X4-LAN-{{VERSION}}-Linux.zip and X4-LAN-{{VERSION}}-Windows11.zip on their respective computers. Use the two archives from the same release folder. Keep all files together in a writable folder; do not run them inside the ZIP viewer.
  • Linux requires Python 3.10 or later and the native Linux game. Disable forced Proton compatibility for X4. Native and Flatpak Steam are supported. Windows does not need Python.
  • Close X4 before installing or removing the mod. Steam may remain open.

Upgrading from the previous version

Extension settings can differ between profiles. Check the Extensions menu in the isolated test profile too. If additional third-party mods remain enabled there, return to the main menu without saving, disable them, quit X4 and use the test starter again. Disabling a mod in your normal profile alone may not change the test profile.

Upgrade both players and the server. The older Windows-only 5.0.2 update does not include these gameplay changes.

Close both test games and stop the old server. In each old package, run its numbered 5 removal command. Then install the new matched pair. Do not copy files over an existing installation or mix package pairs. The installer retains backups and refuses to overwrite an unrecognised mod folder. Older archives remain available as a rollback.

2 · Install and open the Linux server

  1. Open the unpacked X4-LAN-{{VERSION}}-Linux folder in your file manager. Right-click empty space and choose Open Terminal Here.
  2. Install:
    bash 1-INSTALL.sh
    The installer detects the game and creates the isolated test profile 45841. Select the correct Steam installation if prompted.
  3. Start the server:
    bash 2-START-SERVER.sh
    The live console appears in this terminal. Move it to your second monitor and enlarge it. If your file manager executes the script without a terminal, the starter opens a separate Konsole, GNOME Terminal, Xfce Terminal or xterm window. If double-clicking opens an editor or asks for permissions, use the terminal command above.
  4. Keep the server window open. Ctrl+C stops the server. Starting this same package again opens a status viewer if the server is already running; Ctrl+C in that viewer closes only the viewer. An old v3 server or another package cannot provide the new dashboard—stop it first.

Reading the console

FieldMeaning
RUNNING / playersThe relay is running. P1 and P2 count only authenticated game connections. A successful standalone connection test does not occupy a player slot.
WAITINGNo game has connected to this slot during the current server run.
CONNECTEDThe slot has a current server lease. Its IP and source port appear beside it.
NO UPDATES / TIMED OUTNo valid player update for at least 2 seconds / the 30-second lease expired. The last address and event remain visible. This does not distinguish a network failure, stalled game, closed game or adapter failure.
Updates/s / last updateReceived valid position or idle messages and their age. The 2-second warning does not terminate a session; both server and clients use 30 seconds. These values are not game FPS or ping. Position data become stale after 0.75 seconds.
Host simulationWorld/economy revision and time since its last change observed by the console. A paused host may stop changing these values. Pending trade/container counts are also shown.
Relay CPU / RAMCPU percentage of one logical core and peak relay memory. These measure the relay process, not X4 or graphics-driver work.
Game callbacks/s / max gapHow often each game's adapter ran and its largest observed gap during the sampling window. Useful for identifying a stalled game; not a measured rendering FPS counter.
Ship authority / pilotWhich player publishes the ship's movement, and who currently holds its controls. Pilot 0 means the cockpit is vacant.
Shared missionCombined Energy Cell deliveries, target kills and completion. The 25,000-credit reward goes into the shared treasury once.
Recent eventsConnections, lost updates, timeouts and server start/stop, with elapsed timestamps.

The console refreshes twice a second. Detailed snapshots are written to logs/server-*.jsonl; logs/server-status.json holds the current snapshot. These files contain IP addresses but no session keys. Successful packet sends do not prove delivery to the remote game.

3 · Choose the correct address: LAN or ZeroTier

On the same physical LAN, use the Linux host's Ethernet or Wi-Fi IPv4 shown in the console. When playing remotely through ZeroTier, both computers must join the same network and be authorised. Give your friend the Linux host's ZeroTier Managed IPv4, shown on the console's ZeroTier row. Do not use the guest's address, a device/network ID or the host's ordinary home-network address. Omit any /24 suffix.

The server accepts connections on all local IPv4 interfaces, UDP port 45841. Your own Linux game continues to use 127.0.0.1. ZeroTier may be connected after the server starts; its address list refreshes every ten seconds. Direct public-internet port forwarding is not part of this prototype. ZeroTier adds an encrypted network path; the mod protocol itself does not add encryption.

4 · Install and check Windows

  1. Double-click 1-INSTALL.cmd. Enter the Linux host's LAN or ZeroTier IPv4. The installer locates Steam and X4; select the game folder containing X4.exe if necessary.
  2. While the Linux server is running, double-click 2-TEST-CONNECTION.cmd. Expect CONNECTION OK. This confirms a matching server/package reply, not that the Windows game has loaded the mod.
  3. If you entered the wrong IP, close X4, run 5-REMOVE-MOD.cmd and install again with the correct address. This updates both the test command and the in-game connection.

The CMD wrappers apply PowerShell's execution-policy override only to that process. They do not change the stored system policy. An organisation's policy can still block execution. No administrator permissions are requested automatically by the installer.

5 · Start the test worlds

  1. Keep the Linux server open. In a second terminal in the package folder run:
    bash 3-START-X4-TEST.sh
  2. On Windows run 3-START-X4-TEST.cmd.
  3. Both starters ask Steam for a new creative sandbox in isolated profile 45841. Avoid conflicting custom Steam launch options. If the game presents a start configuration, use the default creative start with the same small ship and weapons in Argon Prime.
  4. Wait until both players are in the pilot seat with full flight control. The mod waits around ten seconds before creating the bubble.
  5. Expect LAN Player 1/2, LAN Target 1/2, two cargo containers, and LAN Trading Station Alpha/Beta. Targets start 600 m ahead, containers about 160 m to the side/front, Alpha about 5 km ahead, Beta about 8 km to its side. A stationary donor freighter is part of the fixture.
  6. Check that the server shows both players receiving updates. A spawned ship alone does not prove a remote connection.
Protect your saves: Autosave is disabled only in profile 45841. Do not save manually or quicksave, and never load your main save for this test. The mod refuses to activate outside this test profile. The starter stops if the test profile contains saves; it does not delete them. Existing profile settings are backed up before installation.

Test graphics: installation and each test launch apply 1920×1080 exclusive fullscreen, Low graphics and a 60 FPS limit to profile 45841. The previous configuration is backed up when changed. X4 fullscreen is enabled and borderless mode is disabled; the operating system ultimately controls display presentation. Other profiles are not edited. This reduces rendering work; it is not a verified fix for connection loss.

6 · Shared gameplay checks

Start in the original pilot seat. Both players belong to the same faction and share 200,000 credits. The two shared ships retain their identities, cargo and damage when pilots exchange cockpits or travel between sectors. The old ±50 km cube is removed. NPC scene positions and lifetimes follow the host; NPC interactions, other stations and the wider economy remain independent; Alpha and Beta remain the only shared trading stations. Avoid SETA and the Escape pause menu. Travel-drive/highway fidelity needs more testing.

  1. Containers: At the starting position, run 6-COLLECT-CONTAINER on each computer (Linux: bash 6-COLLECT-CONTAINER.sh). Each ship's assigned container must be within 250 m. Expect 20 Energy Cells per ship and both containers removed on both computers. Repeating pickup must not duplicate cargo. The ordinary cargo magnet is not integrated.
  2. Movement and sector travel: Move and rotate, fly beyond 50 km from the start, and compare the remote ship. Then both travel through the same gate. Verify that both shared ships appear in the destination and keep updating, without returning to Argon Prime. Check the console if updates stop.
  3. Docking and pilot handoff: Dock at Alpha. One player leaves the cockpit and walks onto the station. The other enters that ship, takes its vacant controls and undocks. Verify the new pilot in the server console and the same cargo aboard. Repeat in the opposite direction. An occupied cockpit is refused; the first pilot must leave it. Players on foot are invisible. Passengers aboard moving replicas remain experimental.
  4. Buy: At Alpha, use X4's ordinary Trade menu with the shared ship you currently pilot. Each ship buys 10 Energy Cells at 14 credits. Stay docked until Trade completed. After the container step, both ships carry 30 cells, Alpha has 280 cells and the common treasury has 199,720 credits. Both players should see this same balance.
  5. Sell and share progress: Dock at Beta. Sell 10 Energy Cells from each ship at 17 credits. Both ships now carry 20 cells, Beta has 420 and the common treasury has 200,060 credits. The Cooperative Trial mission should record 20/20 delivered for both players. Either pilot can perform either delivery.
  6. Weapons and mission completion: Destroy LAN Target 1 and LAN Target 2, initially 600 m ahead of the spawn points. Compare firing and damage. Both players share the two kills; the mission completes and the treasury receives 25,000 credits once. With only the trades above, the final balance is 225,060 credits. Reconnecting must not pay again. This is a purpose-built co-op quest; ordinary vanilla quest chains are not yet shared.
  7. Other goods: Energy Cells, Food Rations, Medical Supplies, Hull Parts, Refined Metals and Silicon Wafers support variable quantities and mixed baskets. Alpha starts with 300 of each, Beta with 400. Money is shared; stock and cargo are checked by the Linux host game.

Reconnect and friendly-fire destruction — run after trade and mission checks

  1. Keep both games and the relay running. Interrupt the guest's network for about 40 seconds, then restore it. The client should reconnect automatically and retain one copy of each ship, cargo, pilot authority and shared mission progress. Do not interrupt an active trade for the first check.
  2. Destroy one shared ship while a player is aboard. Friendly fire remains enabled. The occupant should eject into a spacesuit; both connections should remain active. Ship ownership and original player slot do not determine who is ejected. Destroyed ships and cargo stay destroyed.
  3. Use the remaining player ship to hit the suit. Spacesuit weapons are not replicated. The player should respawn at the nearest accessible, non-hostile station in the current sector. The prototype protects the one-hull-point suit until teleportation completes. The survivor can leave their cockpit so the respawned player can take that ship. There is no automatic replacement ship.

Walking avatars remain disabled. Appearance, walking animations, equipment and dialogue are not synchronized. Local replicas may use different dock pads. A player can share a ship as a passenger, but moving passenger views need further real two-computer testing.

Interrupted or partial trade: The client retries the same request ID. Do not place another order. For a partial or uncertain result, retain diagnostics and restart both worlds and the relay. Native transfers cannot safely be rolled back. Multiplayer sessions are not persistent.

A proxy stays present during a disconnect to preserve cargo. Automatic reconnect requires the same games and relay to remain running. Restarting either game or the relay requires two new test worlds. NPC combat, equipment, cargo and ownership changes, other markets, construction, ordinary cargo containers, the full universe economy and save/load remain outside the shared scope. The first co-op quest does not make all vanilla quests cooperative.

Linux firewall — only if the connection test fails

First identify the active firewall zone for the LAN or ZeroTier interface. An interface without an explicit zone uses the default zone:

firewall-cmd --state
firewall-cmd --get-active-zones
firewall-cmd --get-default-zone

Replace YOUR_ZONE with that zone. Open only the server's UDP port, temporarily for two hours:

sudo firewall-cmd --zone=YOUR_ZONE --add-port=45841/udp --timeout=2h

Do not disable the whole firewall. If firewalld is absent, check the firewall actually used on that host. The rule expires automatically; to remove it earlier:

sudo firewall-cmd --zone=YOUR_ZONE --remove-port=45841/udp

8 · Stop and remove

Close both games, then press Ctrl+C in the original server console. Run 5-REMOVE-MOD on both computers to archive the installed mod into the package's backups folder. The isolated profile remains; no saves are deleted. Start X4 normally through Steam afterwards. Restore your other mods before loading a main save that needs them.

Typical isolated profile locations: native Linux ~/.config/EgoSoft/X4/45841 (or under XDG_CONFIG_HOME); Flatpak Steam ~/.var/app/com.valvesoftware.Steam/.config/EgoSoft/X4/45841; Windows Egosoft\X4\45841 under the Windows Documents folder, including redirected Documents folders.
