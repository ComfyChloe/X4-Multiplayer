HEALTH GUEST PROBE: SYNTHETIC-HOST PHASE CONTRACT (dev only, PR #36)
Scope: one native Linux GUEST (p2) piloting co-op ship 2, the real relay, and a synthetic p1
host controller; isolated owned profile, disposable world. It covers guest-side code: HBASE
adoption, MD Base/Based, Authority fences, the WORLD guard, local readbacks/reports and the
keepalive watchdog. The host-side checks stay in tools/dev/HEALTH-FUNCTION-PROBE.txt. Not gameplay
acceptance.

INSTALL (harness)
Guest client config: coop=true, fire2=true, pilot_health=true, health_probe=true,
test_profile="45841" (owned isolated profile), slot p2. Copy tools/dev/health_guest_probe.lua into ui/,
registered AFTER ui/health_game.lua, and tools/dev/health_guest_probe.xml into md/. The guest pilots
ship 2 (it enters it before phase 1). Evidence in the guest debug log:
  [X4LAN] HEALTH_GUEST_PROBE ...  (op order, frames, 20 Hz samples, local damage, injections)
  [X4LAN] HEALTH_PROBE written Base ...  (native readback right after each production Base)
  [X4LAN] HEALTH_AUTHORITY / HEALTH_BASE / HEALTH_KEEP_WATCHDOG   (production lines)
plus the controller's relay transcript (HEALTH frames received as the host).

SYNTHETIC HOST (p1) COMMAND INTERFACE, via the real relay
- HELLO as p1. Send WORLD|1|lease|rev|17 values at 10 Hz, with rev = phase * 1000 + n
  (increasing). The guest probe reads the phase from that revision. Ship 2's hull/shield are
  values 4/5. Keep the other values valid and constant.
- To end the guest's generation: HSTALE|1|lease|2|gen (the relay honours it from p1 for the
  current generation only).
- Read the guest's HEALTH frames forwarded by the relay (HEALTH|1|hostLease|guestLease|2|gen|seq|
  hull|shield) and the relay's HGEN.

PHASES with PASS criteria
1  Handover, rev 1001..: WORLD ship 2 = 64.5 / 30.
   PASS order: frame HBASE gen=G -> op Authority gen=G own=false -> op Base gen=G -> 'written Base'
   readback 64.5/30 -> op Based 2|G -> op Authority gen=G own=true -> sent HACK (immediately on
   Based) -> sent HEALTH G. The guest sends no HEALTH before its first HACK; HACK repeats on
   every HBASE repeat (0.25 s bound). The meaningful gate is the FIRST HEALTH the controller
   receives (relay-accepted, i.e. after the relay saw HACK). Sent-but-unforwarded HEALTH frames
   (HACK lost or late) are explicit: compare the guest's 'sent HEALTH' seqs with the forwarded
   ones. Samples: own=true auth=G top=G based=G.
2  WORLD guard, rev 2001..: WORLD ship 2 = 40 / 10 for 5 s.
   PASS: samples entity 2 stay at the local value (~64.5/30, shield may recharge), never 40; own
   stays true; the HEALTH frames report the local value.
3  Local scripted damage, rev 3001..: the probe writes hull 50 once on the own ship.
   PASS: local_damage readback 50; the next sent HEALTH (urgent, within ~0.2 s) hull 50; the
   WORLD (still 40) does not overwrite it.
4  Rebase, rev 4001..: WORLD ship 2 = 55 / 20, then send HSTALE gen G.
   PASS: a new HGEN G' > G; op Authority gen=0 ended=G (revocation names G); frame HBASE G' with
   55/20 -> Base/written 55/20 -> Based -> own -> HACK -> HEALTH G' from 55. No sent HEALTH of
   G after HGEN G'.
5  Keepalive watchdog, rev 5001..: the probe suspends ONLY health_game.lua's frame dispatch for
   3 s (MD keeps running) and, as controlled loss, drops incoming HGEN/HBASE locally for that time
   (logged once), so the relay's 0.75 s expiry cannot revoke first. AUTH is untouched; the relay
   ending the generation does not change the AUTH key. No relay change is needed; a relay-side
   loss of HGEN/HBASE to the guest is equivalent. Then the probe injects the old
   Authority(G', own=true) with a fresh window.
   PASS: HEALTH_KEEP_WATCHDOG within ~2 s game time; samples own=false auth=0 closed>=G';
   op Authority gen=0 ended=G' (Lua handled Expired); the injected Authority logs now_own=false
   (no resurrection); no sent HEALTH of G' afterwards; the relay ends G' (stale) and a later
   HBASE G'' is adopted normally.
6  Old baseline, rev 6001..: the probe injects the first HBASE (gen G) once.
   PASS: no op Base for G; samples unchanged; the 'frame HBASE gen=G' line shows valid != G.

NOT COVERED HERE: a real pilot-seat leave and re-entry by the native player (it needs player
action). The protocol-level equivalent (generation end and rebase) is phase 4; the AUTH
transition path is covered by the LuaJIT doubles. Lethal handling is host-side
(HEALTH-FUNCTION-PROBE phase 6).
FAIL: any Base/own of a closed or older generation, a WORLD write on the piloted ship while own,
a resurrected own after the watchdog, a HEALTH frame of an ended generation, probe/production
'STOPPED' or MD errors.

GUEST SOURCE AUDIT (remaining edge cases, with what covers them)
- Authority ordering, revocation naming, the own claim and the watchdog fence: covered by
  interpreter tests (tests/test_health_md.py) and phases 1/4/5.
- A Base queued just before a revocation can still execute and write the host baseline of the
  ended generation. Its Based is refused, no pilot value results, and the host value is
  canonical. Accepted residual.
- The WORLD dead guard ('le 0' while own) means a guest whose pilot value is lethal only learns of
  its death from the host's published 0 (after LifeTick). That is intended: one death authority.
- A guest that never receives HGEN for its AUTH revision (e.g. revision skew after a relay
  restart) stays host-authoritative: safe, no stall beyond the next snapshot.
