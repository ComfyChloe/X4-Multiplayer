FIRST CHECKOUT (Fedora, Bazzite or another Linux development machine)
For this private repository, Git needs its own GitHub authentication. Being
signed into Firefox alone is not sufficient. If this laptop is not configured,
use GitHub CLI's browser flow:
  gh auth login --hostname github.com --git-protocol https --web
  gh auth setup-git
On standard Fedora, install missing tools with:
  sudo dnf install git gh python3 python3-pip
Do not use that OS-install command on Bazzite or Fedora Atomic variants; use
their supported package workflow. A configured SSH/PAT workflow also works.
GitHub passwords do not authenticate HTTPS Git operations.
References: https://cli.github.com/manual/gh_auth_login
            https://packages.fedoraproject.org/pkgs/gh/gh/

1. Keep any existing project folder unchanged until local edits are secured.
   Clone into a new sibling folder:
     git clone https://github.com/Lith7ium/X4-Multiplayer.git X4-Multiplayer-current
     cd X4-Multiplayer-current
2. Create this machine's own Python environment:
     python3 dev/bootstrap.py
3. Run all checks, including real local UDP and LuaJIT tests:
     .venv/bin/python dev/check.py
   No game installation is needed for these checks. They do not launch X4.
   Local UDP must be permitted; missing dependencies or skipped tests are failures.

Python 3.10+ and Git are required. Standard Fedora can install missing tools with
its package manager; Bazzite should use its supported immutable-OS workflow.
The Python relay itself has no third-party runtime dependency. Development tests
use pinned lupa 2.8 with its LuaJIT runtime. Do not copy .venv between computers.
The complete suite currently targets Linux x86_64: tests/test_lua.py loads the
Linux native transport directly. Windows contributors can use Linux x86_64 WSL2
or a Linux host for these checks; native Windows game/launcher tests are separate.

USING AN EXISTING LAPTOP CHECKOUT
First inspect it with git status and git remote -v. Commit or otherwise back up
local edits before fetching. If it is not a Git checkout, keep it and use the
fresh sibling clone above. Do not run reset --hard or overwrite the old folder.
Compare any old edits deliberately; the current source already includes changes
made after the original 6.0.0 transfer.

BEFORE CHANGING COMPUTERS
For a branch used by one developer at a time, finish a coherent change, run the
relevant checks, then:
  git status
  git add <the source files you changed>
  git commit -m "Describe the change"
  git fetch origin
  git pull --ff-only
  git push
On the other machine, start with a clean checkout and git pull --ff-only.
If history has diverged, inspect and integrate both sets of changes explicitly;
do not reset or rewrite shared history. Concurrent contributors use separate task
branches and reviewed PRs as described in CONTRIBUTING.txt. A remote repository
does not synchronize uncommitted files, conversations or private agent memory.

LOCAL DATA
Keep generated packages, logs, credentials, installation metadata and backups in
.local/ or outside the checkout. Ignore rules exclude those files. The tracked
extension/ui/config.lua is intentionally inert and contains no session secret.
Never replace it with a machine's installed configuration. Session keys are
generated by host setup and imported by guests, outside the repository.
Game installations, saves, Steam libraries and graphics settings are machine-local.
The presence of this source checkout does not install or launch X4.

PACKAGES / LIVE TESTS
Record exact-version checks first, then build a new INTERNAL pair:
  python3 distribution/build_packages.py .local/playtest/<new-folder-name> --runtime-cache <verified-runtime-cache>
For 7.3.0 this creates inert Windows/Linux host-or-guest archives with verified
portable runtimes. Host setup generates a fresh invitation; guest setup imports it.
The runtime cache uses distribution/public/runtimes.json only as an existing
dependency hash registry; the build remains INTERNAL on profile/port 45841. Install using the generated launchers on each machine. Linux paths
are discovered locally; no old PC/laptop game path is hard-coded in the package.
The host prepares one pristine creative starting save in isolated profile 45841;
both roles load its verified snapshot with autosave disabled. UDP45841 and
TCP45844 are required. Restarting resets to the starting world, not saved progress.
Read distribution/README.txt and distribution/NEXT-TEST.txt for the current flow.
Do not rebuild or overwrite sealed archives to update documentation.

The existing native transport binaries are included for Linux x86_64 and Windows
x64. Source is in native/net.c. Rebuilding both requires Zig 0.15.2:
  python3 native/build.py --zig /path/to/zig --platform both
Ordinary Python/Lua changes do not require rebuilding the transport.

The optional native engine harness is dev/native_world_test.py. It requires a
known installed internal package and explicit install/launch actions; it is never
called by bootstrap or automated checks. It stores evidence under .local/ and
accepts --game /path/to/X4 to select this machine's native installation. Read its
source before using it to replace an installation. Run a host capture before
using the guest --replay option. dev/validate_native_world.py checks its evidence.

Do not invoke distribution/public/build.py for routine internal development.
Public packages require a new explicit user request. No Neresco source, binary
or framework is part of this repository's multiplayer implementation.
