1. Numeric generation seed
x4lan/world_start.py validates a shared world recipe: opaque world ID, a numeric
seed, gamestart, build, mod digest and DLC/extension identity. It emits the actual
-seed:NUMBER argument for a fresh world and rejects conflicting config seed/load
settings or mismatched measured content. It never edits config/content.xml.
The numeric seed is distinct from the existing PR18 "seed" native-save bundle.
A same-number recipe is a hypothesis about initialization, not proof of identical
station layouts or synchronized simulation. Fresh host/guest generation remains
UNTESTED. Source documentation confirms the colon syntax and notes config seed
precedence; the latter is explicitly not a new native measurement here:
https://wiki.egosoft.com/X4%20Foundations%20Wiki/Modding%20Support/Running%20X4%20for%20modding/

2. Station catalog agreement
x4lan/station_catalog.py validates bounded native station catalogs and matches
(code, macro, owner, sector) BEFORE comparing pose. Display-code collisions are
allowed only when fixed descriptors disambiguate them; a full-key collision,
missing/extra station, bad coordinate or aliased runtime handle rejects. Position
is never used to guess identity. Rebound local handles are returned only when
ALL stations match within0.05m /0.00001rad. These are ephemeral startup bindings,
not persistent network IDs or safe authority for moving a live docked station.
dev/station_snapshot.py enforces ordered native begin/rows/end/completion markers,
expected capture identity, exact counts and absence of relevant native errors.

3. Persistent host checkpoint repository
x4lan/world_store.py owns a new private directory. Completed native save bytes
are sealed as immutable numbered checkpoints. A writer lock and expected-revision
check reject concurrent/stale publishers. Files are flushed, then HEAD is replaced
atomically. Interrupted staging/orphan directories are preserved but never adopted
as latest. Corrupt committed state fails closed instead of silently selecting an
older world. Earlier checkpoints remain unchanged and source saves are copied.
Native header readback pins generation seed, gamestart, engine build/version and
world GUID; a different-world save cannot advance an existing repository.
Header parsing is bounded and rejects declarations/UTF16; it does NOT validate
all native save contents or prove an engine save-completion callback occurred.
The caller must supply a completed host snapshot.

Targeted tests reopen the repository in another Python process and use real
loopback TCP to deliver revision2 to a client which missed revision1. These are
synthetic save/header and transport tests, NOT native ongoing-world save/resume.
