HOST-CREATED SHIP EQUIPMENT — NATIVE FEASIBILITY EXPERIMENT
20 October 2026 | A:primary | contrib/astra-entity-lifecycle

PURPOSE AND SCOPE
Saved object references preserve equipment on original ships, but ships created
after the pristine snapshot have no matching native object on the guest. Before
adding a creation descriptor to the network protocol, this experiment tests
whether the engine can reconstruct observed hardware/software assignments from
explicit macro and ware lists. It is dev-only and opt-in; no shipping gameplay
or wire contract is changed by the probe.

The probe reads the engine/shield/weapon/turret slots, virtual thrusters and
software of eight distinct native ship macros in the host's sector. It sends
only those macro/ware lists to an MD action. The action generates a loadout,
creates a temporary ship and applies software; Lua reads back the same slots
and removes only that newly created diagnostic ship. Source ships are not
modified. The isolated world is discarded without saving.

GetNumUpgradeSlots/GetUpgradeSlotCurrentComponent, virtual-slot and software
signatures were checked against this PC's installed vanilla X4 UI. The MD
schema accepts the generation/application actions. These checks establish API
shape, not runtime correctness or deterministic slot assignment. The engine may
assign compatible equipment to different slots; the validator rejects that.
Native source/clone maximum hull and shields must also agree, and no provided
hardware macro may remain unused. Both raw captures and failures are retained.

DESCRIPTOR FOUNDATION — NO NETWORK OR CREATION ACTIVATION
The original Python/Lua X4SHIP1 codec records ship macro/owner, zero-based physical
slots, explicit group path/name/macro/count, software and virtual thruster. Its
canonical bounded ASCII representation rejects partial, duplicate, unknown,
noncanonical and oversized data atomically. Group strings use lower-case hex;
software and slot order are canonical. Empty equipment is explicit, with a
mandatory final thruster row (Lua false / Python None means none).
Seven focused tests cover cross-language byte parity, every truncation of a
representative descriptor, invalid numeric/collection inputs and native group
paths. This is an unused pure module: no UI load entry, native call, creation
authorization or transport is introduced. Group descriptors alone still cannot
reconstruct the failed partial-group case; preserve physical slot observations
and reject unsupported reconstruction until an exact engine primitive is proven.

SERIALIZED RECONSTRUCTION FOLLOW-UP — NATIVE PENDING
The explicit --saved --fill-groups --serialized probe encodes native observations
with X4SHIP1, decodes them, then reconstructs equipment inputs from those decoded
fields and the ship macro's static slot/group layout. It verifies physical macro
compatibility, occupied group coverage/counts and rejects unsupported mixed groups
before writing a preset. The live source handle is retained for comparison and
cleanup protection; equipment construction uses decoded macro/owner/slots/groups.
Raw descriptor bytes and actual native clone macro/owner are logged. The validator
can require this mode and rejects missing/unresolved descriptor/identity headers,
wrong owners/macros and serialized hardware differing from source readbacks.
334 tests and the changed MD schema pass. This new native path is not yet run;
the earlier eight-macro native pass did not exercise serialization or networking.

LIMITS
Even a passing primitive does not prove network creation, inventory, ammunition,
crew composition/skills, equipment modifications, docking, destruction, combat,
economy or whole-universe authority. Those require separate descriptors/events,
engine primitives and native cross-PC checks. This work does not change the
independent joint bootstrap source937262c or any public/internal package.
