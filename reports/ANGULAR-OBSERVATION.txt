NATIVE ROTATION OBSERVATION — INTERNAL RESEARCH
20 October 2026 | PR15 | production unchanged from the sealed 7.1.1 candidate

WHY THIS EXISTS
The bcde58f projectile experiment exceeded its unchanged .002 native firing-basis
gate in one phase. Existing pre-correction logs ran after coop.frame, so zero
angles there did not rule out drift between render frames. This diagnostic wraps
the actual cooperative frame and reads before and after it, then records native
MD orientation and the weapon-fired basis with timestamps. It never writes
position or velocity. The original projectile fixture and thresholds are unchanged.

MEASURED OBSERVATIONS
2932 pre/post frames, 2932 native MD readbacks, 24 independently correlated shots.
All four phases have six shots. The first three use production orientation only:

Phase       settled frames  max pre angle  max post angle  median derived rate
stationary       183          .001078974        0              .050736066
rendered         182          .001156552        0              .057314846
physical         184          .001401028        0              .080900695

Angles are radians; rates are rad/s. The rate is the maximum absolute wrapped
Euler component change from the prior post-frame sample to the current pre-frame
sample, divided by elapsed game time. It is NOT a native angular-velocity getter,
a body-axis angular vector, or a validated production input.

Native readback delays in those settled windows span .011610 to .021315 seconds.
The independent MD basis agrees with small nonzero rotation after correction.
Maximum at-shot basis errors are .000827331, .000907168 and .001352970; the native
reference is .000896094. Shot correlation uses the last UI frame processed by
this MD observer, which need not be the latest rendered frame.

This establishes between-frame rotation in this fixture despite post-frame zeros.
It does not identify the exact engine/controller mechanism. The fourth native
phase retains the existing fixture's external orientation hold after coop.frame;
its derived rate cannot be interpreted as free rotation. Logging adds frame work;
these timings are observations, not general performance measurements.

PROJECTILE RESULT AND LIMIT
This repeat passes the ORIGINAL projectile controls, including the unchanged
.002 gate, and all 24 trajectories are sampled. The prior bcde58f failure remains
valid evidence on the same production code. No production fix was introduced,
so repeatability under frame-time variation and real aim/hit behavior remain open.
No sustained angular override was introduced. Such an override requires an explicit
coordinate/ownership contract and native rotation-control release checks, including
local pilot takeover; the existing linear throttle check alone is insufficient.
