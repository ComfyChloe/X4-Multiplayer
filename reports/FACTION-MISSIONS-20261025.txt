FACTION MISSIONS — FIRST NATIVE ORDINARY-MISSION ADAPTER — 25 OCTOBER 2026

Status and scope
Sourcecba4391, draftPR45: https://github.com/Lith7ium/X4-Multiplayer/pull/45
Source-only INTERNAL work, stacked on NPC combat PR44. No new package, launcher
activation or public release. Source faction_missions=false remains inert.
The existing Cooperative Trial is unchanged. This is NOT universal mission sharing.

The first adapter connects the stock GM_Destroy_RarelyOnSight mission family:
ordinary contracts requiring a number of matching enemy ships to be destroyed.
The host keeps the original GM/RML instance, matching rules, timers, completion,
failure and reward actions. A guest can accept a shared host offer and abort the
shared mission through its native mission interface. Both see the same objective
count. The guest's admitted NPC hits execute on the real host NPC and the stock
player-faction kill event advances the ordinary mission, even in another sector.
No guest-supplied objective count or success claim is accepted.

Only standalone, visible offers without inventory-item rewards are admitted.
Mission threads, hidden offers, plots and other mission families are not admitted.
The source host's ordinary offer generator remains responsible for generating
contracts; this does not generate extra offers around a remote guest. Already
running missions from loaded campaign saves are not imported by this adapter.
Source NPC-combat restrictions still apply: supported stock guns, free-flying S/M
main hull/shields, current identity/pilot generations. Boarding, capital surface
components and unsupported weapons do not acquire acceptance through this work.
Credits are paid once by stock host GM and use the existing treasury replication.
Reputation remains authoritative on the host; guest reputation display and shared
personal inventory are not implemented here. Timers execute on the host; this
first guest presentation does not reproduce the native countdown or proximity
voice hints. Other ordinary local guest missions are not made cooperative.

Architecture and protocol
x4lan/missions.py: authenticated host-only MSTATE records; guest MREQ ACCEPT/ABORT.
ui/mission_protocol.lua: matching bounded ASCII envelope/UTF-8 text codec.
ui/mission_game.lua: native publication, atomic receipt, command retries, MD ACKs.
md/x4lan_missions.xml: native registry, execution-time authority/revision/clock
checks, standard-offer acceptance and native guest mission/offer presentation.
gm_destroy_rarelyonsight.xml and rml_destroy_rarelyonsight.xml: small original
additive hooks, plus a guarded shared-abort event. Original mission/reward code
stays in the installed game. Every applied XPath is unique after earlier changes.
Both server package copy lists use the shared runtime copier, including missions.py.

IDs are never reused within a host lease. Revisions, immutable contract metadata,
monotonic progress and terminal states prevent rollback and duplicate completion.
Checksummed multipart records tolerate loss/reordering; terminal records support
late join. Changed records are prioritized over retained history. Limits: 256
contracts per host session, 24 chunks of 500 bytes, 256/4096/512 UTF-8 bytes for
name/description/objective. Rewards are bounded by the protocol integer limit.
The relay stores facts, not executable cues, mission scripts or reward commands.
Commands resolve only a registered native cue and repeat current-state checks
when MD executes. Virtual stock giver actors legitimately have exists=false;
acceptance uses the live native offer and its original actor/offer handler.
