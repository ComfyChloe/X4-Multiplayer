MEASURED RESULT
Same Xperimental Shuttle, six weapons, identical sector orientation, 24 native
shots. All four controls had 56 position intervals and six correlated native
velocity/trajectory readbacks. Ship speeds derived from sector positions were
0, 100.000, 100.001 and 99.993 m/s respectively. Native speeds were 0, 0, 100,
100 m/s. Median projectile lateral velocities (sector X) were:
- Stationary: -1.086 m/s.
- Production pose-driven motion at 100 m/s: 0.343 m/s.
- Pose-driven motion with explicit native 100 m/s: 100.132 m/s.
- Native translation with orientation correction: 101.866 m/s.
Forward projectile velocity was approximately 2300 m/s in every case.
The four measured controls and all 24 trajectories passed strict validation;
no MD/probe errors or malformed readbacks were found. Normal save bytes and
actual save timestamps were unchanged. Game and test relay closed afterward.

This establishes that the current pose-driven motion does not give this ship
its corresponding native velocity, and its bullets omit the lateral motion
that is present with native velocity. Weapon spread means these medians are
not an exact trajectory-equivalence claim. General aiming/hits remain untested.

CONTROL AND API LIMITS
The diagnostic explicitly holds orientation at zero in EVERY case, preserving
actual position. The native-translation case suppresses production network
position application, but still corrects orientation. It is not uncontrolled
flight. The synthetic pilot sends NAV2/FIRE2; a real Linux engine fires bullets.
Native MD .velocity is cluster-relative but expressed in component-local
rotational axes. Trajectories use sector-relative positions. The setter's frame
at nonzero headings and differently oriented parent spaces needs its own test.
The UI speed display is a separate value, not used as native speed acceptance.
