INTENDED BEHAVIOR
Develop a build-pinned, opt-in Windows scheduler that runs full simulation ticks
at 60 Hz while rendering the latest completed state at any available rate. Keep
the existing variable-step path as a fallback. Fixed timing is not evidence of
multiplayer determinism; RNG, attention, worker ordering and platform FP behavior
remain separate problems.

signature checker and task evidence. No x4lan_net transport changes. No protocol,
package, source config, normal installation or save changes. A future Lua/config
integration must remain false by default and be reviewed separately.

STAGE 1 — FIXED 60 HZ AT A 60 HZ PRESENTATION CAP — 25 OCTOBER 2026
Implementation (opt-in, X4LAN_FIXEDTICK_MODE='fixed60' -> native.start('fixed60')):
- FrameTick already has a fixed-dt path: when movie capture is active it loads
  dt from g_movieCaptureFrameTime (0x6adfc60). The two-byte `je` at 0xfa3302
  (74 08, inside the verified frame_tick_dt signature) becomes `66 90` with an
  aligned 16-bit compare-exchange, and 0x6adfc60 is set to exactly 1/60. The
  capture flag itself is never set, so no screenshots are written. gameTime,
  realTime and unpausedRealTime all advance by the fixed dt.
- Admission additionally requires: capture inactive, frame-rate limiter enabled
  at 60 (0 treated as the engine's 60 default), branch bytes still original.
- Every simulation frame (slot 5) re-checks capture inactive, frame time still
  1/60, limiter still 60 and the patched bytes. Any failure, ownership loss,
  stop() or __gc restores the original branch and capture frame time (unless
  the engine changed it) and records a reason; the probe logs it and stops.
- Stats add fixed, fixed_frames, wall_elapsed, game_elapsed and reason.
Validation:
- Synthetic Windows tests (Zig 0.15.2, -Werror): patch bytes, per-frame guards
  (capture, limiter rate/enable, frame time, foreign bytes, thread), restore on
  every disarm, idempotent stop. Simtick synthetic tests unchanged and PASS.
- Real LuaJIT probe tests 7/7 PASS; actual lua51_64.dll ABI check PASS;
  9 signatures PASS on both the copied and the installed X4.exe.
Native run (same two sandboxes, new worlds, both instances in fixed60):

STAGE 2 — BOUNDED CATCH-UP WITH EXACT PHYSICS SUB-STEPS — 26 OCTOBER 2026
Implementation (X4LAN_FIXEDTICK_MODE='fixed60catchup' -> native.start('fixed60catchup')):
- Uses the Stage 1 dt branch. Every simulation frame (slot 5) adds the wall time
  between FrameTick's stored frame QPC values (0x6b60e80) to an accumulator, takes
  k = whole 1/60 ticks (0..4, 1e-3 tick tolerance), writes the next frame's dt =
  k/60 and sets Jolt's collision-step count (int at *(0x6cf1510), read by
  XPhys::Scene::Step at 0xba8ce before PhysicsSystem::Update) to k (1 when k=0).
  Jolt therefore integrates k sub-steps of exactly 1/60 s. Ticks beyond 4 per
  frame are dropped and counted (bounded catch-up). k=0 frames advance no time.
- No 60 Hz limiter requirement in this mode. Guards each frame: capture inactive,
  frame time and collision steps equal the last scheduled values, patched bytes.
  Disarm restores the branch bytes, the capture frame time and the original
  collision-step count. New signature: physics_collision_steps (0xba8ce, 39 bytes,
  no base relocations in range).
- Limit: game logic (AI, MD, events) still runs once per frame with dt k/60; only
  physics gets true 1/60 sub-steps. Multiple logic steps per frame need a main-loop
  change (later stage). One frame of lag between measured wall time and its dt.
Validation (offline): synthetic tests track wall time within one tick at 30, 60,
144 and 1000 fps, cap a 1 s stall at 4 ticks with 56 dropped, refuse foreign
writes to frame time or collision steps, and restore everything on stop; real
LuaJIT probe tests 8/8; lua51_64.dll ABI PASS; 10 signatures PASS on the copied
and installed X4.exe. No native run yet.

Native run (26 October 2026, one unsandboxed Windows instance from the task-owned
