INTEGRATED INTO DEVELOPMENT SOURCE, ADAPTED AND TESTED
- Raw Windows tasklist bytes instead of locale-dependent text decoding. ASCII
  executable matching retains the running-game refusal; process failures fail closed.
- Missing Steam library drives are skipped before PowerShell Join-Path; stale
  registry roots cannot abort discovery. Both ProgramFiles roots and a validated
  manual Steam-folder fallback are supported.
- Fresh Windows setup selects X4.exe before creating a session. --game and the
  fallback prompt accept the executable or its directory, including Unicode/spaces.
  Paths remain subprocess arguments, never shell fragments. Cancelling makes no session.
- Existing-session recovery is limited to a reset package.json with a complete,
  same-version session.json. It validates the derived package ID, installation
  ownership marker/profile and any existing invitation. Explicit conflicting or
  partial ownership is refused. Changes affect package metadata/config only, with
  exact backups, atomic individual writes and rollback on failure. No token rotation,
  installed configuration rewrite, world replacement or save deletion occurs.
- Repeat setup validates actual installation ownership rather than trusting the
  presence of installation.json. Explicit preference source/keep options now work
  on repeat setup; interactive setup offers reselection. 08-IMPORT-SETTINGS offers
  a choice even with one normal profile. Existing preference backup logic is retained.
- A small settings API contract rejects mixed launcher modules before setup writes.
  It does not require the unsafe review_extra_mods helper added by the submission.
- Extra-mod diagnostics identify the manifest and exact multiplayer selection path.
  Importing display/controls does not copy normal-profile mod selection, so an
  extension disabled in the normal profile can still fail the multiplayer preflight.

EXCLUDED: FLEET/MAP/COMBAT IMPLEMENTATION
Independent, deterministic failures on the supplied source:
1. Lost damage: receive guest shield-loss2 at t=.30, loss3 at t=.33 for the same
   NPC, then take the first relay snapshot at t=.34. Only sequence2/loss3 is sent;
   loss2 is overwritten in guest_hits[entity]. These are deltas, not cumulative
   counters. A one-shot guest UDP send also has no acknowledgement/retry path.
2. Whole adapter stops after fleet shrink: the actual submitted Lua, run with
   the existing engine doubles, publishes17 ships, retains healthCursor15, then
   rescans a one-ship fleet. The next health tick indexes a nil entry and sets
   U.failed=true. captured() resets motionCursor but not healthCursor.
3. Optional map setup defeats its own launcher: enable_map_orders.py copies its
   MD bridge into the installed extension only. Both world launchers compare that
   tree against the package extension. The supplied experimental world launcher,
   on an owned filesystem fixture with the bridge installed as specified, refuses
   with "Installed multiplayer scripts differ from the package." before launch.

Additional source-review limits (not native reproductions): host damage/order MD
execution lacks the complete epoch/guest-lease/sector/pilot fencing used by the
