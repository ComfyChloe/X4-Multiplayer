X4 MULTIPLAYER - ENGINE INSTRUMENTATION POLICY
25 October 2026 | INTERNAL DEVELOPMENT

SCOPE

Until now the project used only supported extension surfaces: Lua UI, Mission
Director, AI scripts and a hook-free native UDP module. Engine instrumentation is
now permitted, following discussion with the project owner. The owner rejected
the opt-in switch for game-loop networking: its supported, validated driver belongs
in the normal runtime and packages. Exact-build checks and native acceptance testing remain
required; unsupported builds must not be patched. It
covers runtime function hooks, game-memory offsets/signatures and patched engine
behavior, for example seeding or replacing RNG state, fixing the simulation
timestep or exposing engine state that the Lua/MD APIs do not provide.

Motivating research: reducing simulation divergence between matched games so a
hybrid of local simulation plus hash-checked resynchronization can replace full
replication of distant NPCs. Instrumentation is a tool for that research, . Windows and Linux builds use
different compilers; do not assume identical floating-point results across them.

Instrumentation changes are reviewed as their own PRs
